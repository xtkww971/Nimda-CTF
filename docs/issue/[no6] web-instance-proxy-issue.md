# [no6][web] 인스턴스 프록시를 ctf-instances 네트워크로 — 컨테이너 이름으로 접속

> 짝 이슈: Judge Server `#35`(agent가 web 인스턴스를 ctf-instances에 띄우고 이름:포트를 돌려줌).
> 근거: Judge Server ADR-0017(격리 경계) 2-2, 2-3.
> 이 이슈는 **웹 백엔드(Spring) 프록시**가 바뀐 접속 방식에 맞추는 작업이다.

### 배경

지금 웹 백엔드의 인스턴스 프록시는 CTF가 돌려준 `host:port`(loopback 임의 포트)로 붙는다.
그런데 배포 형태에서 그 host가 `127.0.0.1`이라, 컨테이너 안에서 도는 백엔드에겐 자기 자신을 가리킨다.
IDE에서 직접 띄울 때만 우연히 됐다(ADR-0017 Problem 2b).

Judge Server 쪽(#35)이 이걸 바꾼다. web 인스턴스는 이제 **`ctf-instances` 네트워크에 뜨고 host 포트를 안 연다.**
접속은 도커 embedded DNS가 풀어주는 **컨테이너 이름**으로 한다.

```
프록시 ──▶ http://{컨테이너 이름}:{컨테이너 포트}
```

그러려면 백엔드(프록시)도 같은 네트워크에 붙어야 하고, 주소를 이름으로 받아 써야 한다.

### 설계

**1. 백엔드를 `ctf-instances` 네트워크에 연결한다**

`backend-blue`/`green`을 `ctf-instances`에 붙인다(웹 레포 compose).
이 네트워크는 Judge Server 쪽에서 `--internal`로 미리 만든다(#35 runbook).
embedded DNS로 컨테이너 이름을 풀려면 같은 네트워크에 있어야 한다.

**2. 프록시 대상을 CTF가 준 이름:포트로 바꾼다**

CTF 응답의 `host`가 이제 컨테이너 이름, `port`가 컨테이너 EXPOSE 포트다.
프록시는 그 값을 **그대로** `http://{host}:{port}`로 쓴다.

* `127.0.0.1`이나 result 캐시의 옛 주소를 쓰지 않는다.
* 이름을 백엔드가 직접 조립하지 않는다(규칙이 바뀌면 깨진다). CTF가 준 host를 그대로 쓴다.

**3. 주소는 매 요청 CTF에 물어본다**

result 캐시(10분)에 든 주소를 그대로 쓰면, 그 사이 컨테이너가 재생성돼 이름·포트가 바뀌면 죽은 주소로 붙는다.
조율자의 내부 조회 엔드포인트로 `uuid → 살아있는지·주소`를 매 요청 받아 쓴다(ADR-0017 2-3).
실패를 연결 불가는 502, 없음은 404로 구분한다.

### 작업

* [ ] 웹 compose: `backend-blue`/`green`을 `ctf-instances`에 연결 (external 네트워크로 참조)
* [ ] 인스턴스 프록시: 대상 주소를 CTF가 준 `host:port`로 (127.0.0.1·캐시 제거)
* [ ] CTF 조회 클라이언트: 조율자 내부 엔드포인트 호출, 502/404 구분
* [ ] 소유권 검사 유지, `OWNER_TTL`을 인스턴스 TTL 이상으로 (보조 기록이 먼저 만료되면 본인이 403)

### 완료 조건

* [ ] 배포 형태(백엔드가 컨테이너)에서 참가자가 web 인스턴스에 붙어 상호작용한다
* [ ] 인스턴스를 재생성해 포트가 바뀌어도 접속 주소(서브도메인)는 그대로다
* [ ] 남의 uuid로는 403, 비로그인은 401
* [ ] CTF가 죽어 있으면 502, 없는 인스턴스는 404

### 이번에 하지 않는 것

* **도메인 분리(ADR-0017 2-1).** `inst-{uuid}.nimda-ctf.kr` 별도 도메인·와일드카드 인증서·쿠키 경계. 별도 이슈.
* **응답 Set-Cookie 제거.** 도메인 분리 전까지의 임시책(ADR-0017). 도메인 이슈와 함께 다룬다.
* **pwn 접속.** raw TCP는 포트 풀이고 프록시를 안 탄다(Judge Server ADR-0020).
* **agent/네트워크 생성.** `ctf-instances`를 만들고 web 인스턴스를 거기 띄우는 건 Judge Server `#35`다.
