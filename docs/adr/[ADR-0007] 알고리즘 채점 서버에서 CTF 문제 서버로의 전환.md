## 1. Context (배경)

이 프로젝트는 원래 사용자가 제출한 코드를 실행해서 정답 여부를 매기는 알고리즘 채점 서버였다.
이번에 nimda.kr에서 사용할 **CTF 문제 서버**로 방향을 바꾸게 되면서, 지금까지 만들어온 구조를
그대로 쓸 수 있는지 다시 살펴봐야 했다.

둘 다 "남이 만든 것을 서버에서 돌린다"는 점은 비슷해 보이지만, 막상 필요한 것은 꽤 다르다.

고려 사항:

* **서버가 하는 일이 달라진다.** 채점에서는 사용자가 코드를 내면 서버가 그걸 실행해보고
  결과를 비교했다. CTF에서는 참가자가 정답 문자열(플래그)만 제출하고, 서버는 그게 맞는지만
  확인하면 된다. 훨씬 단순한 일이다.
* **대신 문제 자체를 계속 띄워둬야 하는 경우가 생긴다.** 웹 문제나 시스템 해킹 문제는
  참가자가 직접 접속할 수 있는 서버가 살아 있어야 한다. 지금 쓰는 isolate는 프로그램을 잠깐
  실행하고 끝내는 용도라 이런 형태를 감당하지 못한다.
* **지켜야 할 방향이 반대가 된다.** 채점에서는 사용자 코드가 격리된 환경을 빠져나오면 사고였다.
  그런데 CTF의 시스템 해킹 문제는 참가자가 그 안에 침입하는 것 자체가 정답이다. 그래서
  "이미 안에 들어와 있다"고 보고, 그 바깥(서버 본체, 다른 참가자의 환경)을 지키는 쪽으로
  생각을 바꿔야 한다.
* 문제 종류마다 필요한 게 다르다. 파일만 내려받으면 되는 문제도 있고, 접속할 서버가 필요한
  문제도 있어서 한 가지 방식으로 전부 처리하기 어렵다.

## 2. Decision (결정)

코드를 실행하고 채점하던 부분을 걷어내고, **문제 환경을 띄우고 관리하는 서버**로 구조를 바꾸기로 했다.

* **정답 확인은 웹 서버(Spring Boot)에서 바로 처리한다.** 문자열 비교라 별도 서버나 대기열을
  거칠 이유가 없다.
* **isolate 기반의 실행·채점 부분은 걷어낸다.** 대신 접속이 필요한 문제는 컨테이너로 띄우고,
  문제에 따라 참가자마다 따로 하나씩 만들어준 뒤 일정 시간이 지나면 회수한다.
* **기존에 만들어둔 것 중 두 가지는 그대로 살린다.** 메시지가 유실되지 않는 대기열(ADR-0004)과,
  권한이 큰 작업을 따로 떼어놓는 구조(ADR-0005)다. 둘 다 문제 환경을 만들고 정리하는 일에
  오히려 더 잘 맞는다.
* **한 번에 다 바꾸지 않고 문제 종류별로 나눠서 진행한다.** 파일만 주면 되는 문제(리버싱,
  포렌식 등) → 다 같이 접속하는 문제 → 참가자별로 따로 띄워주는 문제 순서다. 각 단계가 끝날
  때마다 그만큼의 문제는 실제로 낼 수 있는 상태가 된다.

이 결정으로 ADR-0006(채점 로직에 isolate 사용)은 더 이상 유효하지 않다. ADR-0002는 S3에 두는
파일이 테스트케이스에서 참가자용 첨부파일로 바뀌고, ADR-0004와 0005는 쓰임새만 달라진 채
유지된다.

## 3. Consequences (결과 및 영향)

### 🟢 장점

* **지금 방향을 바꾸는 부담이 크지 않다.** 채점 기능은 아직 끝까지 완성된 적이 없어서
  운영 중인 것을 옮기거나 데이터를 이전할 일이 없다.
* **가장 까다로웠던 부분이 통째로 없어진다.** isolate를 쓰려고 씨름하던 권한 설정 문제들이
  더 이상 필요 없어진다. 컨테이너 쪽에서 이미 정리되어 있는 영역이기 때문이다.
* **핵심 구조는 살아남는다.** 대기열과 권한 분리는 버리는 게 아니라 쓰임새만 바뀐다.
  특히 권한 분리는 CTF에서 더 중요해진다.
* **단계별로 나눠서 진행할 수 있다.** 첫 단계만 끝내도 리버싱·포렌식 같은 문제로 워게임을
  열 수 있어서, 전체가 완성될 때까지 기다릴 필요가 없다.

### 🔴 단점 / 개선안

* **만들어둔 코드를 꽤 많이 지우게 된다.** isolate를 공부하고 붙인 시간이 코드로는 남지 않는다.
  * 다만 격리와 권한 제한이라는 개념 자체는 컨테이너 설정에 그대로 쓰이므로, 공부한 내용이
    사라지는 것은 아니다. 지운 코드는 태그로 남겨서 필요하면 다시 꺼내볼 수 있게 한다.
* **잘못됐을 때의 피해가 커진다.** 채점에서 최악은 결과가 틀리는 정도였지만, CTF에서는
  참가자가 서버를 통째로 장악할 수도 있다.
  * 문제 환경은 처음부터 강하게 격리된 상태로 띄우고, 그 안에서 바깥 인터넷이나 내부망으로
    나가지 못하게 막아둔다. 이건 나중에 추가하기 어려우므로 시작할 때부터 기본값으로 잡는다.
* **관리할 것이 늘어난다.** 채점 서버는 일이 끝나면 알아서 정리됐지만, 문제 환경은 계속
  떠 있는 데다 주소도 하나씩 갖는다. 다 쓴 환경을 제때 정리하지 못하면 자원이 계속 쌓인다.
  * 상시 운영이라 특히 중요한 부분이라, 회수가 실패하면 바로 알 수 있게 해둔다.
* **세부 기술은 아직 정하지 않았다.** 어떤 방식으로 격리할지, 문제 주소를 어떻게 나눠줄지,
  문제를 어떤 형식으로 등록할지 등은 각각 별도 ADR로 정리한다.
