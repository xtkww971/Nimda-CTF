## 1. Context (배경)

온라인 저지 시스템에서 제출된 사용자 코드를 안전하게 실행하기 위해 실행 환경(Sandbox)을 결정해야 한다.

고려 사항:

* 제출 코드가 호스트 시스템에 영향을 주지 않아야 함.
* CPU, 메모리, 실행 시간 등을 제한할 수 있어야 함.
* 채점 종료 후 실행 환경이 깨끗하게 정리되어야 함.
* 다양한 언어와 채점 방식으로 확장 가능한 구조를 지원해야 함.

## 2. Decision (결정)

사용자 코드 실행 환경으로 **Isolate Sandbox**를 채택한다.

채점 요청마다 독립된 Isolate Box를 생성하여 컴파일 및 실행을 수행하고, 채점 완료 후 Box를 제거하여 실행 환경을 초기화한다. 또한 Isolate에서 제공하는 CPU 시간, 메모리, 프로세스 수 등의 제한 기능을 활용하여 안전하게 사용자 코드를 실행한다.

## 3. Consequences (결과 및 영향)

### 🟢 장점

* **격리된 실행 환경:** 사용자 코드가 독립된 Sandbox 내부에서 실행되어 호스트 시스템 및 다른 채점 작업에 영향을 주지 않는다.
* **자원 제한 지원:** 실행 시간(Time Limit), 메모리(Memory Limit), 프로세스 수 등을 손쉽게 제한하여 무한 루프나 자원 고갈 공격을 방지할 수 있다.
* **높은 안정성:** 채점이 종료되면 Sandbox를 제거하여 이전 실행 결과나 임시 파일이 다음 채점에 영향을 주지 않는다.
* **확장성:** 언어별 컴파일러 및 실행 명령만 추가하면 다양한 프로그래밍 언어를 동일한 방식으로 지원할 수 있다.

### 🔴 단점 / 개선안

* **초기화 오버헤드:** 채점마다 Sandbox를 생성하고 제거하는 과정에서 일정한 성능 오버헤드가 발생한다.

  * 개선안: Isolate Box Pool을 도입하여 Sandbox를 재사용하는 방안을 추후 검토한다.
* **Linux 의존성:** Isolate는 Linux 환경을 전제로 하므로 Windows에서는 직접 사용할 수 없다.

  * 개선안: 채점 서버는 Linux(Docker) 환경에서만 운영하도록 표준화한다.
* **운영 복잡도:** Sandbox 설정 및 권한 관리가 필요하므로 초기 구축 난이도가 증가한다.

  * 개선안: 초기 설정을 자동화하고 운영 문서를 함께 관리한다.
